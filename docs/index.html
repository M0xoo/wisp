wisp runs your coding agents in the background. When one finishes, you don't get a 4,000-line transcript — you get a 30-second presentation: the diff, the tests, the decisions, and what's next.

Works with Claude Code · Codex · opencode · Cursor · Antigravity

macOS stable · Linux & Windows beta

How it works

  1. 01

    You hand off a task.

    From the launcher, or wisp "fix the flaky auth test" in any folder.

  2. 02

    The agent works. A lot.

    Reads, greps, edits, re-runs tests. Thousands of lines you were never going to read.

  3. 03

    wisp distills it.

    The agent ends with structured blocks. wisp renders them — real diffs from its own tool calls.

  4. 04

    You read the highlights.

    Thirty seconds. Then follow up, take over, or mark it done.

Features

An inbox for your agents.

Fire off as many tasks as you like. wisp sorts them, surfaces the ones that need you, and stays out of the way otherwise.

A queue, not a chat log

One feed, grouped: Needs you on top, Working with a live one-line status, Done below.

Needs you 1
Working 2
Done 2

Agents can ask. Mid-run.

Every agent gets an ask_user tool. Your answer goes straight back into the running session.

Old v1 tokens are still in prod. Keep backward-compat?
↳ · delivered to running agent

Real diffs

Captured from the agent's own tool calls. Not a summary of a change — the change.

- await sleep(50) + clock.tick(ttl + 1) + expect(store.isExpired(t)).toBe(true)

Take over, any time

Press T. Your terminal opens in the project, session resumed. Terminal, iTerm, Ghostty, Warp, cmux, kitty, WezTerm, Windows Terminal and more.

The vocabulary

Nineteen blocks. Infinite reports.

Agents compose presentations from a fixed set of animated blocks — so every report is skimmable, and none look the same.
