How it works

  1. 01

    You hand off a task.

    From the launcher, or wisp "fix the flaky auth test" in any folder.

  2. 02

    The agent works. A lot.

    Reads, greps, edits, re-runs tests. Thousands of lines you were never going to read.

  3. 03

    wisp distills it.

    The agent ends with structured blocks. wisp renders them — real diffs from its own tool calls.

  4. 04

    You read the highlights.

    Thirty seconds. Then follow up, take over, or mark it done.

Subagents

Give the lead a team.

A Claude Code run hands tests to Codex, research to opencode and UI work to Cursor. Each member has its own harness, model and a Use for note that tells the lead when to pick it.

  • ×N copies — Codex ×3 gives the lead three Codex agents that run side by side.
  • One report card per delegated task, each opening into that subagent's own presentation.
  • Subagent edits count as the lead's: same diff, rollback and Ship it.
  • Save as preset and reuse the team on the next launch.

Recipes & triggers

Prompts that run themselves.

A recipe is a prompt you send again and again; {version} becomes a field to fill in. Run it from the launcher, ⌘K or a terminal. Triggers start sessions while wisp is open: on a schedule, when CI fails, or when an issue gets a label.

  • A recipe can pin a project, harness, model and mode.
  • GitHub triggers poll with your gh login. Nothing has to reach your machine.
  • Issue triggers start in Plan mode: issue text is untrusted.

Machines

Run agents on your other computers.

A dev box, a GPU server, a cloud VM. Give wisp an SSH host and press Connect: it signs in with your keys, starts wisp over there and tunnels back. Run on sends one prompt to this computer and any machines at once.

  • Found on this computer — hosts from ~/.ssh/config, Tailscale and known_hosts, one click to add.
  • One task card with a row per machine. Worktrees, diffs, rollback, ask_user and Ship it work there too.
  • Take over opens ssh -t in your terminal, session resumed.
  • Nothing new listens on the network. Agents keep running when your laptop sleeps.

    FAQ

    Questions, answered.

    What is wisp?

    wisp is a free, open-source launcher for AI coding agents. It runs agents like Claude Code and Codex on your projects in the background. When one finishes, it hands you a short animated presentation (the diff, test results, commits and next steps) instead of a long transcript.

    Which coding agents does wisp support?

    Claude Code (claude), OpenAI Codex (codex), opencode, Cursor CLI (cursor-agent), Antigravity CLI (agy) and Grok Build (grok). Each harness is one adapter file, so adding another is small.

    How do I install wisp?

    Install Node.js 20 or later and sign in to at least one supported agent CLI. Then run npx wisp-agents to open the desktop app, or npx wisp-agents "fix the flaky auth test" to launch a task in the current folder.

    Is wisp free?

    Yes. wisp is MIT-licensed and free. You use your existing Claude Code, Codex, opencode, Cursor, Antigravity or Grok account, and those providers bill as usual.

    Does my code leave my machine?

    wisp itself is a local server. Sessions and state are plain JSON in ~/.wisp. Your code only goes to the agent provider you choose, same as running that CLI directly. wisp sends anonymous usage stats with no prompts, paths or agent output. Turn them off with WISP_TELEMETRY=0 or DO_NOT_TRACK=1.

    Can I take over a session in my terminal?

    Yes. Press T and wisp opens your terminal in the project with the agent's resume command, for example claude --resume <id>. It works with Terminal, iTerm, Ghostty, Warp, kitty, WezTerm, Windows Terminal and more.

    Can other tools send tasks to wisp?

    Yes. wisp ships an MCP server (wisp mcp), an agent skill, a scriptable CLI, a JS SDK, an OpenAPI-described HTTP API and webhooks. You can hand tasks to it from other agents, editors, scripts or CI.
