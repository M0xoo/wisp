Engineering as code · open source

Your AI dev team, and everything it did, as code.

Declare your agents, crew, machines and workflows in one file. Run Claude Code, Codex, Cursor and every other agent from it, on any of your computers. Remember every task next to the code it wrote, so anyone can see why it's there and pick it up again.

See a wisp.yml
  wisp.yml
wisp: 1

agents:
  reviewer: { harness: codex, effort: high, mode: plan }
  fixer:    { harness: claude, model: opus }

crew:
  - name: Ada
    role: Reviews every PR before I wake up
    agent: reviewer
    schedule: every weekday at 7

machines:
  - { name: studio, ssh: me@studio.local }

connectors:
  - { name: linear, env: { TOKEN: ${secret:linear} } }

workflows:
  release-check:
    on: { schedule: every day at 2 }
    tasks:
      tests:  { agent: fixer, prompt: Run the suite }
      fix:    { needs: [tests], agent: fixer,
                goal: tests pass, on: studio }
      audit:  { matrix: { harness: [claude, codex] },
                prompt: Audit the diff }

One file

Everything your agents need, declared.

The same way infrastructure as code made servers reviewable and reproducible, wisp makes your agent team a file in your repo. Clicking in the app and editing the file change the same thing.

AgentsNamed profiles: harness, model, effort, mode, account, tools. "reviewer" means the same thing everywhere.
CrewLong-lived teammates with a role, a schedule, a notebook and a team they delegate to.
MachinesYour laptop, a dev box over SSH, a cloud computer. Say where each task runs.
WorkflowsTasks with needs, conditions, fan-out across agents, goals, retries and one budget.
ToolsMCP servers and wisp's own tools, per agent. Secrets stay out of the file.
RulesWho may start what from Slack or Telegram, spend limits, what happens when a run fails.

Tasks are code too

Share a task. Rerun it. Try it on another setup.

Every task keeps what was asked and the exact setup it ran with. Send it to a teammate as one file, rerun it from the same commit, or replay last week's work on your new team to see which one is better.

Your repo remembers

Every line knows which task wrote it.

The tasks that built your code live next to it, in .wisp/. Ask why a line is there, read the prompt and the decision behind it, and pick up last month's work on today's code.

Three ways in, one engine

The app, the terminal, or your own code.

The desktop app, the terminal UI and the CLI are all built on the same commands. Anything you can do in one, you can do in the others, and in a script.

App

Mac, Windows, Linux and your phone. One list across all your computers, a report instead of a transcript.

Desktop · Android

Terminal

wisp tui for the full app in your terminal, or wisp "task" to run one and answer it inline. "Check the error above" reads what just failed.

TUI · CLI

Code

TypeScript and Python SDKs, generated from the same commands: start tasks, stream them, apply formulas, from your own scripts.
