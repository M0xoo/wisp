# trywisp.dev (`docs/`)

The site sells wisp to someone who hasn't tried it. Be ambitious there: real product visuals,
live demos and a layout that tells a story, not a generic landing page. It still uses wisp's look
(one accent, hairlines, the same type) so the product feels like the site promised.

## Files

- Hand-written: `docs/index.html`, `docs/style.css`, `docs/main.js`, `docs/spells.js`, `docs/cloud.html`,
  `docs/integrations.md`, `docs/privacy.md`, `docs/install.sh`.
- Generated by `node scripts/site.mjs` and gitignored: `agents/`, `guides/` (from
  `scripts/guides.mjs`), `integrations`, `changelog`, `404`. Edit the scripts, not the output.
  `scripts/site.mjs` must handle CRLF input.

## Rules

- **Bust the cache.** When you change `style.css`, `main.js` or `spells.js` (or another script it
  loads), bump its `?v=` in `docs/index.html`, or visitors keep the old file.
- **Install text must work as pasted.** Env vars go on the shell side of a pipe
  (`curl -fsSL … | WISP_VERSION=x bash`). Run every command you change.
- **Download comes last** among the install tabs until the apps are signed, with a per-OS hint
  (on a Mac, the `curl … | bash -s -- --app` install and *Open Anyway*). npx is first.
- Download links use `releases/latest/download/<name>`; never put a version in an asset name.
- A CTA pointing at a form scrolls to the form's `id` and focuses its input; `#top` does nothing
  when the page is already at the top.
- Every way in (npx, npm, curl, brew, the app) is offered at the top and the bottom, kept in step.
- Check the page in real Chrome at desktop and phone widths, light and dark, before calling it done,
  and read the install text you changed.
